六种禁止的合并（§4）

§4.2E-absent + A-in-force被压成「已批准」（隐瞒没查）或「未授权」（否认存在的权）
§4.3E-contradicted被压成 E-absent —— 冲突变成缺口，冲突信息当场丢失
§4.4E-verified被读成「主张为真」；未写方法名即不可复核
§4.5E-verified + A-revoked证据好被当成有权 —— 往放行方向错
§4.6A-unknown被读成 A-in-force（默认放行）或 A-revoked（默认拒绝）

符合性测试（§6）— 标蓝的两条是底线

T-4R-5.4.2记录取不到 → 必须报 A-unknown 底线
T-2R-5.2.3冲突证据 → 不得等于 E-absent 的报法 底线
T-1R-4.1.2(E-absent, A-in-force) → 不得给单值
T-3R-5.2.2E-verified → 必须给方法标识符
T-5R-5.4.3不可达时的决定 → 须与可达时可区分
T-6R-5.5.1变更两侧各一决定 → 须记版本
T-7R-5.5.3不发事件改值 → 再查须能发现
T-8R-5.6.3重评改值 → 前值须仍可恢复
T-9R-5.7.2跨变更的长动作 → 分段归属可恢复
